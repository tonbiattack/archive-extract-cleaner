# ZipSweep（旧称 archive-extract-cleaner）

> **安全上のお知らせ:** 差分スキャンとアーカイブのハッシュキャッシュの再利用は一時停止しています。通常スキャン・完全再スキャンとも内容を再照合します。このページのキャッシュ高速化に関する説明や過去の測定値は、再利用の安全性が確認されるまで適用されません。

> **ご利用前に:** このアプリはファイルをごみ箱へ移動する操作を含みます。**重要なデータは事前にバックアップしてください。** 削除はごみ箱への移動だけで完全削除は行いませんが、移動した容量はごみ箱を空にするまでディスクの空き容量として戻りません。詳細は [SECURITY.md](SECURITY.md) を参照してください。

**ZIP が残っているなら、解凍済みのフォルダは要らない。**（`.7z` / `.rar` も同じ考え方で扱えます）

**ZipSweep**（リポジトリ名・旧称 `archive-extract-cleaner`）は、ZIPなどの圧縮ファイルと解凍済みフォルダを照合し、**内容が完全一致する解凍済みフォルダだけをWindowsのごみ箱への移動候補として提示する** Windows 向けのデスクトップアプリです。スキャンとプレビューは読み取り専用で、移動は候補を選んで最終確認した場合だけ実行します。

| 手元の状態 | 結果 |
| --- | --- |
| `photos.zip` + `photos/`（全ファイルと空ディレクトリまで一致） | `photos/` だけごみ箱へ移動できる。ZIPは保持 |
| `photos.zip` + `photos/`（追加・不足・内容変更あり） | 両方保持。差分を表示 |
| `photos.zip` のみ | 保持 |
| `photos/` のみ | 保持。転送候補として扱う |
| `photos.7z` / `photos.rar` + `photos/`（7-Zip CLI 導入済み） | `.zip` と同じく照合する。一致すれば `photos/` だけごみ箱へ移動できる |
| `photos.7z` / `photos.rar`（7-Zip CLI 未導入） | `UNVERIFIED` として両方保持。`photos/` は削除候補にならない |

同じ親ディレクトリの `name.zip` と `name/` を対応付け、アーカイブをディスクへ展開せずエントリをストリーミングでSHA-256比較します。フォルダを消す前にアーカイブが本当に同じ内容かを確かめたい、という用途だけを担当します。`.zip` は標準機能で読めます。`.7z` / `.rar` は [7-Zip](https://www.7-zip.org/) の CLI を使うため、未導入の環境では `UNVERIFIED` として両方を保持します（[7z / RAR 対応](#7z--rar-対応)）。

HDD側の存在確認・転送・HDD内の重複削除は行いません。詳細な仕様は [docs/SPEC.md](docs/SPEC.md) を参照してください。

## なぜ必要か

ダウンロードしたZIPを解凍したまま放置すると、同じデータがZIPとフォルダの二重で残ります。かといって、ZIPがあるという理由だけでフォルダを消すのは危険です。解凍が途中で止まっている、後からファイルを足した、別のZIPを解凍した、といった違いは名前からは分かりません。

このアプリは**名前の一致を候補抽出にしか使わず**、削除候補にするには内容の完全一致を要求します。一致しなければ何もしません。迷う要素が1つでもあれば、両方を残します。

- **名前が同じでも消さない** — 全ファイル・空ディレクトリ・SHA-256まで一致した組だけが候補
- **ZIPは勝手に消さない** — 既定は「フォルダのみ移動」。ZIPの移動は明示選択と追加警告が必要
- **完全削除しない** — Windowsのごみ箱へ移すだけ。移動できなければ中止して理由を表示する
- **読み取り専用で始まる** — スキャン・詳細・中身プレビューはファイルを変更しない

## 判定

| 判定 | 意味 | 動作 |
| --- | --- | --- |
| `KEEP_ARCHIVE` | 対応フォルダなし | アーカイブを保持 |
| `KEEP_DIRECTORY` | 対応アーカイブなし | フォルダを保持（転送候補） |
| `DELETE_CANDIDATE` | 全ファイル・空ディレクトリまで一致 | フォルダのみごみ箱へ移動する候補 |
| `DELETE_CANDIDATE_IGNORABLE` | 差分がアーカイブ側の補助ファイル（`__MACOSX/`、`.DS_Store` 等）だけ | フォルダのみごみ箱へ移動する候補（差分を表示） |
| `MISMATCH` | 追加・不足・内容変更あり | 両方保持 |
| `AMBIGUOUS` | 同名候補が複数、または比較方式が複数成立 | 両方保持 |
| `UNVERIFIED` | 破損・暗号化・リンク混入・上限超過・検証中の変更など | 両方保持 |

対応付けのルール:

1. 同じ親ディレクトリ内の `name.zip` ↔ `name/` を第一候補にする（`.7z` / `.rar` も同じ規則）。
2. アーカイブ内の最上位ディレクトリが1つだけの場合は、それを除去した構造とも比較する（`photos.zip` 内 `photos/a.jpg` ↔ `photos/a.jpg`）。
3. 名前一致だけでは削除候補にせず、必ず内容を検証する。
4. 名前が異なる場合は自動対応しない。複数候補は `AMBIGUOUS`。
5. フォルダのみの項目は、各対象ルート直下のフォルダ、およびアーカイブと同じ親にある兄弟フォルダを対象にする。アーカイブを含むコンテナフォルダ（先祖ディレクトリ）は一覧のノイズを避けるため除外する。

完全一致の条件:

- アーカイブ内の正規化済み相対パス集合と、フォルダ内の通常ファイル／ディレクトリ集合が一致
- 各ファイルの**展開後バイト列**のSHA-256が一致
- 空ディレクトリも比較対象
- アーカイブ内の絶対パス、`..`、重複パス、大小文字衝突、Windows予約名、末尾の空白/ドット等は `UNVERIFIED`
- シンボリックリンク、ジャンクション、リパースポイントを含むフォルダは走査・移動しない
- 検証中にアーカイブまたはフォルダの内容が変化した場合は `UNVERIFIED`

### 名前が異なる組の対応

`photos.zip` と `photos (1)/` のように、重複時に付く接尾辞だけが違う組も候補にします。対応する接尾辞は ` (1)`、` - コピー`、` - Copy`、`_2`、` のコピー` です。

- 完全一致するフォルダがある場合は、必ずそちらを優先します
- 名前の対応は**候補抽出だけ**に使い、削除候補にするには従来どおり内容の完全一致が必要です
- 候補が複数ある場合は `AMBIGUOUS` のままにします
- 名前差で対応した組は、一覧と詳細に「名前差」バッジを表示します

### 補助ファイルのみの差分（`DELETE_CANDIDATE_IGNORABLE`）

ZIPとフォルダで OS やアーカイバが自動生成するファイルの有無だけが違う場合、それだけで `MISMATCH` にすると実用上ほぼ全件が該当してしまいます。次の条件をすべて満たす場合だけ、`DELETE_CANDIDATE_IGNORABLE` として削除候補にします。

- 差分が **ZIP側にのみ存在する** 補助ファイル／補助ディレクトリだけ
- それ以外の共通ファイルはパス集合が一致し、**SHA-256 も一致**
- フォルダ側にしか無いファイルが1つも無い

対象は `__MACOSX/`、`.DS_Store`、`._*`（AppleDouble）、`Thumbs.db`、`desktop.ini`、`.Spotlight-V100`、`.Trashes`、`.fseventsd`、`.localized`、`.apdisk`、`ehthumbs.db`、`*.tmp`、`*.part`、`*.crdownload` です。

フォルダ側にしか無いファイルは対象外です。ユーザーが意図して置いた可能性があり、削除すると情報が失われるためです。差分の内容は詳細ペインと判定理由に表示され、移動確認ダイアログにも補助ファイルを含む旨の警告が出ます。

フロントエンドは `frontend/dist` の静的ファイルをWailsが埋め込むため、Node.js や npm は不要です。

## ビルドと起動

```powershell
git clone https://github.com/tonbiattack/archive-extract-cleaner.git
cd archive-extract-cleaner

go install github.com/wailsapp/wails/v2/cmd/wails@v2.17.1
wails build -clean

.\build\bin\archive-extract-cleaner.exe
```

開発中は次のコマンドで起動できます。

```powershell
wails dev
```

CI（[`.github/workflows/ci.yml`](.github/workflows/ci.yml)）は Windows 上で `gofmt`・`go vet`・`go test`・`wails build` を実行し、exe を成果物としてアップロードします。

表示名は ZipSweep ですが、既存ユーザーの更新とデータ互換性のため、実行ファイル名 `archive-extract-cleaner.exe`、リポジトリ名、設定・ログ等の保存先は変更していません。従来のショートカットも引き続き同じ実行ファイルを指せます。Windows のスタートメニューに登録するときは、既存の実行ファイルを指すショートカットを **ZipSweep** という名前で作成してください。Microsoft Store 配布は検討中で、未提出です。詳細と未検証項目は [Store 配布準備](docs/STORE_READINESS.md) を参照してください。

### 手動配置した場合のアンインストール

自分で配置した実行ファイルとショートカット（スタートメニューの「ZipSweep」または旧名）を削除し、手動で追加したユーザー PATH があれば削除してください。設定・整理状態・操作ログ・WebView2 データは削除されず、`%AppData%\archive-extract-cleaner` と `%LocalAppData%\archive-extract-cleaner` に残ります。不要な場合は、必要なバックアップを取ってから各フォルダを手動で削除してください。

## 使い方

1. 上部の入力欄に対象フォルダを追加するか、「フォルダを選択」で追加します。複数指定できます。
2. 「スキャン」を押します。走査中も一覧・検索・フィルタ操作は可能で、「停止」で中断できます。
3. 検索語と判定フィルタ（全件 / 削除候補 / 不一致 / 未検証 / 保持）で絞り込み、列ヘッダーでソートします。
4. 行を選ぶと右側の詳細ペインに、ZIPとフォルダの対応、一致方式、ファイル数、差分・不一致理由が表示されます。あわせて「中身プレビュー」が表示され、ZIPのみ・フォルダのみ・両方の内容を確認できます。両方存在する場合は「ZIP」「フォルダ」タブで切り替えます。ZIP内のパスは実ファイルのフルパスではないため、コピーした相対パスはZIP内の場所として扱ってください。ダブルクリックでも、存在するフォルダを優先して開きます。
5. 列見出し右端のハンドルをドラッグすると列幅を変更できます。ハンドルのダブルクリックで自動調整、ツールバーの「列幅リセット」で既定値に戻ります。幅は再起動後も保存されます。
6. 一覧のファイル名・パスはドラッグで選択して `Ctrl+C` でコピーできます。右クリックメニューまたは詳細ペインのコピーボタンから、名前・ZIPパス・フォルダパス・親パスをコピーできます。
7. `DELETE_CANDIDATE` の行だけチェックできます。複数選択・`Shift` 範囲選択・「候補を全選択」が使えます。チェックボックス上でマウスを押したまま上下にドラッグすると、開始時の状態（未選択なら選択、選択済みなら解除）を通過した行へまとめて適用できます。端に近づけると自動スクロールします。タッチ操作では通常のスクロールを優先します。
8. 「選択項目をごみ箱に移動」を押すと、項目ごとに「解凍済みフォルダのみ」「ZIPのみ」「ZIPとフォルダの両方」から移動方法を選択できます。最終確認で件数・サイズ・フルパスを確認し、承認後にのみWindowsのごみ箱へ移動します。両方の移動は追加の警告とチェックが必要です。
9. 整理後に残ったデータを転送する場合は「残ったデータをE/F/Gへコピー」を押します。ZIP優先の推奨一覧と、不一致・未検証・曖昧な要確認一覧をレビューして対象を選択し、multi-drive-copy を起動します。コピーは multi-drive-copy 側で実行・確認してください。

> **移動前に必ずバックアップしてください。** ごみ箱への移動はバックアップの代わりにはなりません。本アプリは完全一致をできる限り検証しますが、重要なデータの唯一のコピーを移動する用途には使わないでください。

ごみ箱に移動できない場合（UNC/ネットワークドライブ、ごみ箱非対応ドライブ、容量不足、ロック中など）は**完全削除へフォールバックせず中止**し、理由を表示します。

### 選択状態のルール

- チェックできるのは `DELETE_CANDIDATE` のみです。
- 選択は検索・フィルタ・ソートを切り替えても保持されます。非表示の選択項目も移動確認ダイアログに表示されます。
- 新しいスキャンを開始すると選択は解除されます。
- 移動後は選択を解除し、成功・失敗・スキップの結果を表示します。失敗した行は `UNVERIFIED` として再スキャンまで移動できません。
- 「候補を全選択」は現在の検索・フィルタ条件に一致する削除候補をすべて選択します。

## ごみ箱移動の安全策

- スキャンと詳細表示・中身プレビューは読み取り専用です。プレビューはファイルを展開・変更・削除しません。
- 移動対象は、内容一致を確認した組の「解凍済みフォルダのみ」「ZIPのみ」「ZIPとフォルダの両方」から選択します。ZIPは自動では移動しません。
- 最終確認ダイアログで明示承認した場合のみ移動します。無確認の一括移動はありません。
- 移動直前に各ZIPとフォルダを再照合し、`DELETE_CANDIDATE` でなくなった対象はスキップします。
- 対象ルート自身、ルート外、リンク/ジャンクション混入、再解析不能な対象は拒否します。
- Windowsの `IFileOperation` と `FOFX_RECYCLEONDELETE` を使い、通常のごみ箱へ移動します。ZIPもフォルダも元の名前・場所を保ったまま復元できます。
- ZIPとフォルダの両方の移動は、最後のローカルコピーを失う可能性があるため、通常より強い警告と追加チェックを要求します。転送は行いません。
- 一方の移動だけ成功した場合は部分成功として残存状態を表示し、残った対象だけを再試行できます。
- ごみ箱に移動できない場合は**完全削除へフォールバックしません**。失敗として扱い、理由を結果ダイアログと操作ログに残します。
- UNCパス、ネットワークドライブ、光学ドライブなど、ごみ箱移動に対応しない場所は事前に拒否します。外付けドライブでもごみ箱が利用できない場合は移動に失敗します。
- 移動処理は途中で中断できません。部分的な失敗は結果ダイアログと操作ログに残します。

操作ログ（移動日時・ID・ZIP・フォルダ・成否・エラー）は次の場所に保存され、GUI右上の「操作ログ」からエクスプローラーで開けます。移動したZIP・フォルダはWindowsのごみ箱から「元に戻す」で復元できます。

```text
%LocalAppData%\archive-extract-cleaner\operations.jsonl
```

## 設定と上限

## スキャンキャッシュ（差分スキャン）

> **現在は再利用を停止しています。** サイズ・更新時刻・書庫の中央ディレクトリ情報だけでは内容の同一性を保証できないため、通常スキャンと完全再スキャンのどちらでも前回判定とハッシュを再利用しません。以下は再利用を再開する場合の設計と保存先の説明です。

保存先は次のとおりです。

```text
%LocalAppData%\archive-extract-cleaner\cache\archives.json   ZIPエントリのハッシュ
%LocalAppData%\archive-extract-cleaner\cache\scan.json       前回の判定結果
```

**キャッシュは高速化のためだけに存在し、削除の可否を決めません。**

- ごみ箱移動直前の再照合は、キャッシュの有無にかかわらず必ず実体を再計算します（`moves.go` は `Hashes` を渡しません）。
- 再利用するのは、次のすべてが一致した項目だけです。
  - ZIPのパス・サイズ・更新時刻
  - ZIPの**構造指紋**（セントラルディレクトリのエントリ名・圧縮方式・CRC32・サイズ。圧縮データは読みません）
  - フォルダの指紋（相対パス集合・サイズ・更新時刻・空ディレクトリ）
- `UNVERIFIED`、エラー、移動途中の項目は保存しません。毎回再検証します。
- キャッシュが壊れている・スキーマが古い・ファイルが無い場合は、黙って完全スキャンへ戻ります。

**同サイズ・同更新時刻のままZIPの中身だけ差し替えた**ケースは、構造指紋（CRC32を含む）が変わるため再利用されません。

ツールバーの「完全再スキャン」でキャッシュを無視して全件を再検証できます。設定ダイアログの「キャッシュを破棄」で保存済みキャッシュを削除できます。破棄後の次回スキャンは完全スキャンになります。

### 実測

`go test ./internal/engine -run TestDifferentialScanBenchmark -v` で確認できます。40組のZIP/フォルダ（この開発環境）では次の結果でした。

```text
full scan: 37.8ms, differential scan: 22.1ms
```

**再利用を停止している現在、差分スキャンは完全スキャンより遅くなります。** 停止中もキャッシュの読み書きと記録生成のコストだけが残るためです。この数値は再利用を再開したときの比較用であり、高速化の効果を示すものではありません。

## 容量の内訳（ダッシュボード）

スキャン後に一覧上部へ容量の内訳を表示します。

| 項目 | 内容 |
| --- | --- |
| 回収見込み | 内容一致を確認済みの削除候補の合計。**不一致・曖昧・未検証は含めません** |
| ZIPを保持 | `KEEP_ARCHIVE` のZIPサイズ合計 |
| フォルダを保持 | `KEEP_DIRECTORY` のフォルダサイズ合計 |
| 削減対象外 | `MISMATCH` / `AMBIGUOUS` / `UNVERIFIED` の合計（判定別の件数付き） |
| ごみ箱へ移動した容量 | 実際に移動できたバイト数。成功・部分成功・失敗・スキップの件数付き |

**「回収見込み」と「実際に空いた容量」は別物です。** ごみ箱へ移動しても、ごみ箱を空にするまでディスクの空き容量は増えません。画面にもその旨を常時表示します。

- 表示は**スキャン全体の値**です。一覧を検索・フィルタで絞り込んでも変わりません（絞り込み中は「一覧は N 件に絞り込み中」と併記）。
- 移動後は回収見込みが減り、「ごみ箱へ移動した容量」が増えます。複数回に分けて移動すると累積します。
- 見出しの「−」で折りたためます。

集計は表示専用で、削除の可否判定には使いません。


ツールバーの「CSV書き出し」「JSON書き出し」から、スキャン結果を保存できます。保存先は毎回ダイアログで選びます。ファイルは一時ファイルへ書いてから置き換えるため、途中で失敗しても壊れたファイルは残りません。

CSV の列は固定です（先頭が `id`、`verdict`、`status`、`name`、…、末尾が `zipMoved`、`folderMoved`）。`details` は ` | ` で連結し、`deletable` は削除候補かどうかを示します。Excel で文字化けする場合は UTF-8 対応のエディタか JSON を使ってください。

JSON は `{"generatedAt", "summary", "roots", "items": [...]}` の形で、各項目は CSV と同じ情報を持ちます。外部ツールやAIに渡す場合は JSON のほうが扱いやすいです。

どちらの形式も、**削除の可否を決めるのはスキャン時の判定だけ**です。書き出したファイルを編集しても、アプリ側の判定は変わりません。

## E/F/G の同名アーカイブ検索（既定は無効）

整理対象のアーカイブと同じ名前のファイルが、E/F/G の保存先に既にあるかを横断的に調べます。multi-drive-copy でコピーする前に、重複コピーを避けるための情報として使います。

**同名は同一内容ではありません。** この検索結果は表示専用で、削除の可否や移動の判断には使いません。

### 有効化

`config.json` の `archiveSearch.enabled` を `true` にします。

```json
{
  "archiveSearch": {
    "enabled": true,
    "drives": ["E", "F", "G"],
    "relativePath": "",
    "recursive": false
  }
}
```

保存先は multi-drive-copy と同じ規則です。`relativePath` が空ならドライブ直下、指定すると `E:\<relativePath>` のようになります。

### 使い方

1. スキャンする
2. ツールバーの「E/F/Gの同名を検索」を押す
3. 一覧の「E/F/G同名」列、またはフィルタ「E/F/Gに同名あり」「同名・同サイズ」で絞り込む

セルにマウスを重ねると、見つかったドライブとフルパスが出ます。

### 表示の意味

| 表示 | 意味 |
| --- | --- |
| `—` | 未検索 |
| `なし` | 検索したが同名は見つからなかった |
| `同名・同サイズ` | 同名でファイルサイズも一致。**内容一致は意味しない** |
| `同名・サイズ違い` | 同名だがサイズが異なる |
| `未確認` | ドライブ未接続・アクセス拒否などで確認できなかった |

**`未確認` を `なし` と読み替えないでください。** ドライブが接続されていないだけの可能性があります。ツールバー下の状態表示に、ドライブごとの確認件数と未確認の理由が出ます。

### 制約

- 索引は保存先フォルダ単位で1回だけ作り、項目ごとに全件走査しません。`maxEntries` を超えた場合は打ち切られ、状態表示に「上限で打ち切り」と出ます。
- リパースポイント（ジャンクション・シンボリックリンク）の保存先は、別ボリュームへ抜ける可能性があるため検索しません。
- 検索結果はアプリを再起動すると消えます。スキャンし直した場合も再検索が必要です。

## AI連携（参考情報・既定は無効）

AIは**推薦を表示するだけ**で、削除の可否は決めません。削除できるのは、従来どおり内容の完全一致（または補助ファイルのみの差分）を確認した項目だけです。

- 対象は `MISMATCH` と `AMBIGUOUS` の項目のみ。`UNVERIFIED` と既に削除候補の項目はAIへ送りません。
- 送信するのは証拠（件数・比率・代表的なファイル名・兄弟フォルダ名）だけで、ファイルの内容は送りません。
- APIキーは設定ファイルに書かず、環境変数から読みます。

```powershell
$env:ARCHIVE_CLEANER_AI_KEY = "..."   # ai.apiKeyEnv で変数名を変更できます
```

```json
{
  "ai": {
    "enabled": true,
    "endpoint": "https://api.openai.com/v1/chat/completions",
    "model": "gpt-4o-mini"
  }
}
```

ローカル推論を使う場合は `endpoint` を `http://localhost:11434/v1/chat/completions` などにし、`allowInsecure` を `true` にします。`enabled` が `false` の間はネットワークへ一切アクセスしません。

AIの推薦は操作ログに `action: "ai_suggestion"` として、モデル名・判断・信頼度・証拠ハッシュとともに記録されます。

列幅はWebView2のローカルストレージへ保存され、再起動後に復元されます（`%LocalAppData%\archive-extract-cleaner\webview`）。「列幅リセット」で既定値に戻せます。

## multi-drive-copy 連携

「残ったデータをE/F/Gへコピー」から、スキャン結果をレビューして既存の [multi-drive-copy](https://github.com/tonbiattack/multi-drive-copy) を起動できます。本アプリは転送処理を実装せず、コピー成功の判定や元データの自動削除も行いません。

- ZIPが存在して内容一致する組はZIPだけを推奨します。フォルダしかない場合はフォルダを推奨します。
- `MISMATCH` / `UNVERIFIED` / `AMBIGUOUS` はZIPとフォルダを要確認として表示し、ユーザーが明示選択するまで転送対象にしません。
- 起動前にパスの存在を再確認します。スキャン結果にないパスや消失したパスは転送しません。
- 転送対象が多い場合は、`{"sources":[...]}` 形式のJSONマニフェストを書き、multi-drive-copy の `-SourceListFile` に渡します。Windowsのコマンドライン長制限を超えても全件を渡せます。
- `-Preset` と `-SourceListFile` は multi-drive-copy 側で併用禁止です。大量パスでプリセットが指定されている場合は、プリセットを暗黙適用せずレビュー画面を開き、その旨を警告します。
- 一時マニフェストは24時間より古いものを次回起動時に削除します。子プロセスが読み込む前には削除しません。
- multi-drive-copy の設定・プリセット・競合処理・コピー後の検証・ごみ箱移動はそのまま利用します。
- コピー結果は受信側の明示的な結果プロトコルができるまで本アプリへ反映せず、成功を推測しません。

設定ファイルの `multiDriveCopy` で場所とプリセットを指定できます。

- `scriptPath` 空欄: `%LocalAppData%\Programs\MultiDriveCopy\MultiDriveCopy.ps1` を使用
- `preset` 空欄: multi-drive-copy の設定画面を表示
- `preset` 指定: 小規模な引数連携では保存済みプリセットの直接実行モード。大量パスではレビュー画面を開き、プリセットは適用しません（警告表示）

multi-drive-copy は `Install.ps1` でインストールしておいてください。`-SourceListFile` に対応した版が必要です。古い場合は multi-drive-copy を更新してください。

## 整理と転送は別操作

**重複フォルダを整理しても、E/F/Gへの転送は自動では始まりません。** 次の2通りの運用が可能です。

- **整理だけ行う:** スキャン → 一致した解凍済みフォルダを選択 → 確認後にWindowsのごみ箱へ移動 → そのまま終了。転送ボタンを押す必要はありません。
- **整理してから転送する:** 上記の整理後、ユーザーが明示的に「残ったデータをE/F/Gへコピー」を押す → ZIP優先の推奨候補と要確認候補をレビューして転送対象を選ぶ → multi-drive-copy側でコピー先・コピー後の検証・元データの整理を確認する。

整理時のごみ箱移動と、転送後のコピー元のごみ箱移動は**別の操作**です。後者はmulti-drive-copy側のオプション（初期状態OFF）であり、転送開始や元データ削除が自動的に連鎖することはありません。画面上部のワークフロー表示は案内であり、全工程の実行を義務付けるものではありません。

### ワークフロー

画面上部のワークフロー表示で、現在の段階と担当アプリを確認できます。

| 段階 | 担当 | 内容 |
| --- | --- | --- |
| 整理 | 本アプリ | スキャン、照合、削除候補の確認、ごみ箱移動 |
| 転送・検証 | multi-drive-copy | 転送対象レビュー、E/F/Gへのコピー、全コピー先の検証 |
| 元データ整理 | multi-drive-copy | 検証済みのコピー元をごみ箱へ移動 |

コピー・検証・ごみ箱移動の結果プロトコルは未実装のため、本アプリは起動後の結果を自動反映しません。エラー・中止時は「残ったデータをE/F/Gへコピー」から再試行してください。アプリ再起動時はワークフロー表示が初期段階に戻ります。

## 7z / RAR 対応

`.zip` に加えて `.7z` と `.rar` も照合できます。ZIP と同じ安全条件（パス正規化、SHA-256、空ディレクトリ、リンク拒否）を適用します。

**7-Zip（`7z.exe`）が必要です。** 次の順で自動検出します。

1. 設定ファイルの `archiveTool` に指定したパス
2. PATH 上の `7z`
3. `%ProgramFiles%\7-Zip\7z.exe`、`%ProgramFiles(x86)%\7-Zip\7z.exe`、`%LOCALAPPDATA%\Programs\7-Zip\7z.exe`

見つからない場合、`.7z` / `.rar` は `UNVERIFIED` として保持され、削除候補になりません。ZIP の照合は 7-Zip なしでも動作します。

```json
{
  "archiveTool": "C:\\Program Files\\7-Zip\\7z.exe"
}
```

| 状況 | 判定 |
| --- | --- |
| 一致 | `DELETE_CANDIDATE`（ZIPと同じ） |
| 差分が補助ファイルのみ | `DELETE_CANDIDATE_IGNORABLE`（ZIPと同じ） |
| 追加・不足・変更 | `MISMATCH` |
| パスワード付き | `UNVERIFIED` |
| 分割書庫・未対応圧縮方式 | `UNVERIFIED` |
| 7-Zip 未インストール | `UNVERIFIED` |

`.zip` は標準ライブラリで読むため 7-Zip は不要です。`.7z` / `.rar` だけが 7-Zip CLI に依存します。

**ライセンス**: 7-Zip は LGPL（`7z.dll` の一部に unRAR 制限）です。本アプリは外部プロセスとして呼ぶだけで、バイナリを同梱・再配布しません。

**速度**: 7-Zip CLI の `-so` は複数エントリを指定してもアーカイブ内の格納順で出力するため、エントリ単位で読み出す必要があります（実測 約13ms/エントリ）。ZIP より遅いため、7z / RAR が多い対象ではスキャンに時間がかかります。キャッシュによる短縮は現在停止中です（「スキャンキャッシュ」参照）。

## 制限

- 対応アーカイブは `.zip` / `.7z` / `.rar`（ZIP64、UTF-8/CP437 のファイル名に対応）
- 7z / RAR の検証には [7-Zip](https://www.7-zip.org/) が必要（未インストールなら `UNVERIFIED` として保持）
- HDDとの比較、汎用の重複ファイル検索、同期・コピーは行いません。
- 任意のファイル・フォルダの無条件削除、完全削除は行いません。削除はWindowsのごみ箱への移動だけです。
- 名前が異なるフォルダの自動対応（明示マッピング）は未実装です。
- ごみ箱移動の成否はOSの実装に依存します。UNCパス・ネットワークドライブ・光学ドライブなどは事前に拒否し、それ以外でも移動できない場合は中止します。
- 移動処理は途中で中断できません。
- multi-drive-copy のコピー結果は自動反映しません。結果プロトコルは未実装です。

## コントリビューション

Issue と Pull Request を歓迎します。

1. [仕様書](docs/SPEC.md) の判定・対応付け・安全条件に従う。
2. 「名前が一致しただけで削除候補になる」「ごみ箱に移せないときに完全削除へフォールバックする」挙動を弱めない。
3. 挙動を変えたらテストを追加し、`gofmt`・`go vet`・`go test` を通す。
4. 実際の個人データのパス・ZIPの内容・操作ログをコミットしない。

不具合は [Issue テンプレート](.github/ISSUE_TEMPLATE/bug_report.md) から、セキュリティ上の問題は [SECURITY.md](SECURITY.md) の手順で非公開に報告してください。

## セキュリティと注意事項

**重要なデータは事前にバックアップしてください。** このアプリはファイルを移動する操作を含みます。

- 削除は Windows のごみ箱への移動だけで、完全削除は行いません。ごみ箱非対応の環境では中止して理由を表示します。
- スキャンとプレビューは読み取り専用です。移動は明示操作でのみ実行し、直前に必ず再照合します。
- ごみ箱へ移動した容量は、**ごみ箱を空にするまでディスクの空き容量として戻りません**。
- 7z / RAR の検証には外部の [7-Zip](https://www.7-zip.org/) CLI が必要です。本アプリはバイナリを同梱・再配布しません。
- AI 連携は既定で無効です。有効化した場合のみ集約済みメタデータを送信し、ファイルの内容は送信しません。

詳細と既知の制約は [SECURITY.md](SECURITY.md) を参照してください。
