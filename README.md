# archive-extract-cleaner

ZIPなどの圧縮ファイルと解凍済みフォルダを照合し、**内容が完全一致する解凍済みフォルダだけをWindowsごみ箱への移動候補として提示する** Windows 向け Go デスクトップアプリです。スキャンは読み取り専用で、ごみ箱への移動は候補を選択して最終確認した場合だけ実行します。

- ZIPのみ → 残す（`KEEP_ARCHIVE`）
- 解凍済みフォルダのみ → 残す（`KEEP_DIRECTORY`）
- ZIPとフォルダの全内容が完全一致 → フォルダのみ削除候補（`DELETE_CANDIDATE`）
- 追加・不足・内容変更がある → 両方残す（`MISMATCH`）
- 対応が曖昧 → 両方残す（`AMBIGUOUS`）
- 破損・暗号化・読み取り不可・上限超過など → 両方残す（`UNVERIFIED`）

HDD側の存在確認・転送・HDD内の重複削除は行いません。詳細な仕様は [docs/SPEC.md](docs/SPEC.md) を参照してください。

## 主な機能

- Everything風の一覧画面（仮想スクロール、検索、判定フィルタ、列ソート）
- 列幅をドラッグで変更し再起動後も復元。ハンドルのダブルクリックで自動調整
- セルのファイル名・パスを選択してCtrl+Cでコピー。右クリックメニューと詳細ペインからもコピー可能
- 対象フォルダの複数指定、再帰スキャン、進捗表示、中断、再スキャン
- ZIPをディスクへ展開せず、エントリをストリーミングでSHA-256比較
- ZIP内の単一トップディレクトリを除去した比較（`photos.zip` 内 `photos/a.jpg` ↔ `photos/a.jpg`）
- 削除候補のみを選択可能。複数選択、範囲選択、候補の一括選択
- 項目ごとに「解凍済みフォルダのみ」「ZIPのみ」「ZIPとフォルダの両方」を選んでごみ箱へ移動。両方は追加警告・明示チェック付き
- ZIP・フォルダのごみ箱移動と部分失敗の再試行。移動後は残った側を転送候補へ反映
- 詳細ペインの「解凍済みフォルダを開く」はフォルダの中身を開き、「ZIPの場所を表示」は親フォルダでZIPを選択表示
- 最終確認ダイアログに対象件数・合計サイズ・移動パスを表示
- 移動直前にZIPとフォルダを再照合し、変化があればスキップ
- **Windowsのごみ箱へ移動**し、完全削除は行わない。移動できない場合は中止して理由を表示
- 整理後に残ったZIP/フォルダをレビューし、既存の multi-drive-copy へ引き渡し（ZIP優先、要確認は明示選択）
- 「整理 → 転送・検証 → 元データ整理」の現在段階を表示するワークフローUI
- 操作履歴を JSONL で保存し、GUIから開ける
- サイズ・件数・圧縮率の上限を設定ファイルで変更可能

## 動作環境

- Windows 11（x64）
- [WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)（Windows 11 は通常プリインストール済み）
- ビルドする場合: Go 1.26 以上、Wails CLI v2.17.1

## ビルドと起動

```powershell
git clone https://github.com/tonbiattack/archive-extract-cleaner.git
cd archive-extract-cleaner

go install github.com/wailsapp/wails/v2/cmd/wails@v2.17.1
wails build -clean

.\build\bin\archive-extract-cleaner.exe
```

フロントエンドは `frontend/dist` の静的ファイルをWailsが埋め込むため、Node.js や npm は不要です。

開発中は次のコマンドで起動できます。

```powershell
wails dev
```

CI（`.github/workflows/ci.yml`）では Windows 上で `gofmt`・`go vet`・`go test`・`wails build` を実行し、exe を成果物としてアップロードします。

## 使い方

1. 上部の入力欄に対象フォルダを追加するか、「フォルダを選択」で追加します。複数指定できます。
2. 「スキャン」を押します。走査中も一覧・検索・フィルタ操作は可能で、「停止」で中断できます。
3. 検索語と判定フィルタ（全件 / 削除候補 / 不一致 / 未検証 / 保持）で絞り込み、列ヘッダーでソートします。
4. 行を選ぶと右側の詳細ペインに、ZIPとフォルダの対応、一致方式、ファイル数、差分・不一致理由が表示されます。詳細ペインの「解凍済みフォルダを開く」はフォルダの中身を開き、「ZIPの場所を表示」は親フォルダでZIPを選択表示します。ダブルクリックでも、存在するフォルダを優先して開きます。
5. 列見出し右端のハンドルをドラッグすると列幅を変更できます。ハンドルのダブルクリックで自動調整、ツールバーの「列幅リセット」で既定値に戻ります。幅は再起動後も保存されます。
6. 一覧のファイル名・パスはドラッグで選択してCtrl+Cでコピーできます。右クリックメニューまたは詳細ペインのコピーボタンから、名前・ZIPパス・フォルダパス・親パスをコピーできます。
7. `DELETE_CANDIDATE` の行だけチェックできます。複数選択・Shift範囲選択・「候補を全選択」が使えます。
8. 「選択項目をごみ箱に移動」を押すと、項目ごとに「解凍済みフォルダのみ」「ZIPのみ」「ZIPとフォルダの両方」から移動方法を選択できます。最終確認で件数・サイズ・フルパスを確認し、承認後にのみWindowsのごみ箱へ移動します。両方の移動は追加の警告とチェックが必要です。
9. 整理後に残ったデータを転送する場合は「残ったデータをE/F/Gへコピー」を押します。ZIP優先の推奨一覧と、不一致・未検証・曖昧な要確認一覧をレビューして対象を選択し、multi-drive-copy を起動します。コピーは multi-drive-copy 側で実行・確認してください。

**移動前に必ずバックアップしてください。** ごみ箱への移動はバックアップの代わりにはなりません。本アプリは完全一致をできる限り検証しますが、重要なデータの唯一のコピーを移動する用途には使わないでください。

ごみ箱に移動できない場合（UNC/ネットワークドライブ、ごみ箱非対応ドライブ、容量不足、ロック中など）は**完全削除へフォールバックせず中止**し、理由を表示します。

### 選択状態のルール

- チェックできるのは `DELETE_CANDIDATE` のみです。
- 選択は検索・フィルタ・ソートを切り替えても保持されます。非表示の選択項目も移動確認ダイアログに表示されます。
- 新しいスキャンを開始すると選択は解除されます。
- 移動後は選択を解除し、成功・失敗・スキップの結果を表示します。失敗した行は `UNVERIFIED` として再スキャンまで移動できません。
- 「候補を全選択」は現在の検索・フィルタ条件に一致する削除候補をすべて選択します。

## 判定と対応付け

| 判定 | 意味 | 動作 |
| --- | --- | --- |
| `KEEP_ARCHIVE` | 対応フォルダなし | ZIPを保持 |
| `KEEP_DIRECTORY` | 対応ZIPなし | フォルダを保持 |
| `DELETE_CANDIDATE` | 全ファイル・空ディレクトリまで一致 | フォルダのみごみ箱へ移動候補 |
| `MISMATCH` | 追加・不足・内容変更あり | 両方保持 |
| `AMBIGUOUS` | 同名候補が複数、または比較方式が複数成立 | 両方保持 |
| `UNVERIFIED` | 破損・暗号化・リンク混入・上限超過・検証中の変更など | 両方保持 |

対応付けのルール:

1. 同じ親ディレクトリ内の `name.zip` ↔ `name/` を第一候補にします。
2. ZIP内の最上位ディレクトリが1つだけの場合は、それを除去した構造とも比較します。
3. 名前一致だけでは削除候補にせず、必ず内容を検証します。
4. 名前が異なる場合は自動対応しません。複数候補は `AMBIGUOUS` です。
5. フォルダのみの項目は、各対象ルート直下のフォルダ、およびZIPと同じ親にある兄弟フォルダを対象にします。ZIPを含むコンテナフォルダ（先祖ディレクトリ）は一覧のノイズを避けるため除外します。

完全一致の条件:

- ZIP内の正規化済み相対パス集合とフォルダ内の通常ファイル／ディレクトリ集合が一致
- 各ファイルの展開後バイト列のSHA-256が一致
- 空ディレクトリも比較対象
- ZIP内の絶対パス、`..`、重複パス、大小文字衝突、Windows予約名、末尾の空白/ドット等は `UNVERIFIED`
- シンボリックリンク、ジャンクション、リパースポイントを含むフォルダは走査・移動しない
- 検証中にZIPまたはフォルダの内容が変化した場合は `UNVERIFIED`

## ごみ箱移動の安全策

- スキャンと詳細表示は読み取り専用です。
- 移動対象は、内容一致を確認した組の「解凍済みフォルダのみ」「ZIPのみ」「ZIPとフォルダの両方」から選択します。ZIPは自動では移動しません。
- 最終確認ダイアログで明示承認した場合のみ移動します。無確認の一括移動はありません。
- 移動直前に各ZIPとフォルダを再照合し、`DELETE_CANDIDATE` でなくなった対象はスキップします。
- 対象ルート自身、ルート外、リンク/ジャンクション混入、再解析不能な対象は拒否します。
- Windowsの `IFileOperation` と `FOFX_RECYCLEONDELETE` を使い、通常のごみ箱へ移動します。ZIPもフォルダも元の名前・場所を保ったまま復元できます。
- ZIPとフォルダの両方の移動は、最後のローカルコピーを失う可能性があるため、通常より強い警告と追加チェックを要求します。転送は行いません。
- 一方の移動だけ成功した場合は部分成功として残存状態を表示し、残った対象だけを再試行できます。
- ごみ箱に移動できない場合は**完全削除へフォールバックしません**。失敗として扱い、理由を結果ダイアログと操作ログに残します。
- UNCパス、ネットワークドライブ、光学ドライブなど、ごみ箱移動に対応しない場所は事前に拒否します。外付けドライブでもごみ箱が利用できない場合は移動に失敗します。
- 移動処理は途中で中断できません。部分的な失敗は結果ダイアログと操作ログに残します。

操作ログ（移動日時・ID・ZIP・フォルダ・成否・エラー）:

```text
%LocalAppData%\archive-extract-cleaner\operations.jsonl
```

GUI右上の「操作ログ」からエクスプローラーで開けます。移動したZIP・フォルダはWindowsのごみ箱から「元に戻す」で復元できます。

## 設定ファイルと上限

GUI右上の「設定」から現在値と設定ファイルの場所を確認できます。初回に「設定ファイルを開く」を押すと既定値のファイルを作成します。変更後はアプリを再起動してください。

列幅はWebView2のローカルストレージへ保存され、再起動後に復元されます（`%LocalAppData%\archive-extract-cleaner\webview`）。「列幅リセット」で既定値に戻せます。

```text
%AppData%\archive-extract-cleaner\config.json
```

```json
{
  "limits": {
    "maxEntries": 200000,
    "maxTotalBytes": 68719476736,
    "maxFileBytes": 17179869184,
    "maxCompressionRatio": 1000
  },
  "multiDriveCopy": {
    "scriptPath": "",
    "preset": ""
  }
}
```

- `maxEntries`: ZIPエントリ数、またはフォルダ内のファイル＋ディレクトリ数の上限
- `maxTotalBytes`: 展開後合計サイズの上限（既定 64 GiB）
- `maxFileBytes`: 単一ファイルの上限（既定 16 GiB）
- `maxCompressionRatio`: 合計展開サイズが 1 GiB を超える場合の圧縮率上限

上限超過は `UNVERIFIED` となり移動できません。0 を指定した項目は既定値に戻ります。

## multi-drive-copy 連携

「残ったデータをE/F/Gへコピー」から、スキャン結果をレビューして既存の [multi-drive-copy](https://github.com/tonbiattack/multi-drive-copy) を起動できます。本アプリは転送処理を実装せず、コピー成功の判定や元データの自動削除も行いません。

- ZIPが存在して内容一致する組はZIPだけを推奨します。フォルダしかない場合はフォルダを推奨します。
- `MISMATCH` / `UNVERIFIED` / `AMBIGUOUS` はZIPとフォルダを要確認として表示し、ユーザーが明示選択するまで転送対象にしません。
- 起動前にパスの存在を再確認します。スキャン結果にないパスや消失したパスは転送しません。
- 転送対象が多い場合は、`{"sources":[...]}` 形式のJSONマニフェストを書き、multi-drive-copy の `-SourceListFile` に渡します。Windowsのコマンドライン長制限を超えても全件を渡せます。
- `-Preset` と `-SourceListFile` は multi-drive-copy 側で併用禁止です。大量パスでプリセットが指定されている場合は、プリセットを暗黙適用せずレビュー画面を開き、その旨を警告します。
- 一時マニフェストは24時間より古いものを次回起動時に削除します。子プロセスが読み込む前には削除しません。
- multi-drive-copy の設定・プリセット・競合処理・コピー後の検証・ごみ箱移動はそのまま利用します。
- コピー結果は受信側の明示的な結果プロトコルができるまで本アプリへ反映せず、成功を推測しません。

設定ファイルの `multiDriveCopy` で場所とプリセットを指定できます。

- `scriptPath` 空欄: `%LocalAppData%\Programs\MultiDriveCopy\MultiDriveCopy.ps1` を使用
- `preset` 空欄: multi-drive-copy の設定画面を表示
- `preset` 指定: 小規模な引数連携では保存済みプリセットの直接実行モード。大量パスではレビュー画面を開き、プリセットは適用しません（警告表示）

multi-drive-copy は `Install.ps1` でインストールしておいてください。`-SourceListFile` に対応した版が必要です。古い場合は multi-drive-copy を更新してください。

## 整理→転送ワークフロー

画面上部のワークフロー表示で、現在の段階と担当アプリを確認できます。

1. **整理**（本アプリ）: スキャン、照合、削除候補の確認、ごみ箱移動
2. **転送・検証**（multi-drive-copy）: 転送対象レビュー、E/F/Gへのコピー、全コピー先の検証
3. **元データ整理**（multi-drive-copy）: 検証済みのコピー元をごみ箱へ移動

コピー・検証・ごみ箱移動の結果プロトコルは未実装のため、本アプリは起動後の結果を自動反映しません。エラー・中止時は「残ったデータをE/F/Gへコピー」から再試行してください。アプリ再起動時はワークフロー表示が初期段階に戻ります。

## 役割分担

- 本アプリ: ローカルのZIPと解凍済みフォルダの照合、削除候補抽出、フォルダのごみ箱移動
- 既存の E/F/G 向けコピーツール: HDDへの転送と、同一階層での重複除外
- Krokiet 等: 異なる階層をまたぐ重複整理

HDD上のデータ有無や転送は判定しません。

## MVP対象外

- 7z / RAR、暗号化ZIPの中身判定
- HDDとの比較、汎用重複ファイル検索、同期・コピー
- 任意のファイル・フォルダの無条件削除、完全削除
- 無確認の自動移動、ごみ箱以外の削除方法
- 異なる名前のフォルダの自動対応（明示マッピング）

## 開発

```powershell
gofmt -w .
go vet ./...
go test ./...
wails build -clean
```

主な構成:

```text
main.go / app.go / rows.go   Wailsエントリポイント、GUI API、一覧・集計
internal/engine              走査・ZIPとフォルダの対応付け・進行通知
internal/ziparchive          ZIP構造解析、パス検証、トップ階層除去
internal/fswalk              安全なフォルダ走査（リンク追跡なし）
internal/verify              パス集合と内容の完全一致検証
internal/removal             再確認付きのごみ箱移動（IFileOperation）
internal/oplog               操作ログ
internal/config              上限設定ファイル
internal/winpath             Windowsパス・予約名・リパースポイント検証
frontend/dist                GUI（静的HTML/CSS/JS、ビルド不要）
```

テストは実ファイルシステムの一時ディレクトリ内でのみ破壊的操作を行い、ZIPのみ／フォルダのみ／完全一致／追加・不足・変更／破損・暗号化・CRCエラー／Zip Slip／ZIP64／日本語・空白パス／ジャンクション／検証中の変更／ドライラン無変更／移動拒否条件などを検証します。実際のごみ箱移動は `ARCHIVE_CLEANER_RECYCLE_TEST=1` を指定した場合のみ実行する統合テストで、ZIPファイル・フォルダ双方の移動と復元を確認できます。multi-drive-copy 連携は `Read-SourceListFile` の実装fixtureと、インストール済みの実スクリプト（存在する場合）に対して `sources` スキーマを検証します。
