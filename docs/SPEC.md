# 仕様書 — archive-extract-cleaner

> 暫定安全措置: 8.2節のキャッシュ再利用は一時停止中。サイズ・更新時刻・書庫の中央ディレクトリ情報では内容の同一性を保証できないため、通常スキャンと完全再スキャンの双方で前回判定とハッシュを再利用しない。8.2節の高速化・安全性に関する記述は現時点では適用しない。

## 1. 背景と目的
ダウンロードした ZIP と解凍済みフォルダがローカルに混在している。HDDへ移す前に、ZIPが残っているならZIPを優先し、内容が同一の解凍済みフォルダを整理したい。一方、ZIPが無くフォルダだけならフォルダを保持してコピー対象にしたい。

本ツールの責務は **ローカルの「圧縮ファイル vs 解凍済みフォルダ」の照合と、安全なWindowsごみ箱移動候補の抽出** のみ。HDD転送・HDD上の重複判定・別階層の一般的な重複検出を行わない。

## 2. 対象と非対象
- 初期OS: Windows 11。実装言語: Go。**GUI中心**で操作（CLIは補助・任意）
- MVP対応アーカイブ: .zip（ZIP64、UTF-8/CP437等のファイル名に留意。解釈不能は要確認）
- 非対象（初期）: .7z/.rar、暗号化 ZIP の中身判定、HDDとの比較、汎用重複ファイル検索、同期・コピー
- 入力: 指定した1つ以上のローカルルート。再帰的に走査
- 出力: GUI一覧表示、必要に応じたJSONレポート、明示した場合のみ安全なWindowsごみ箱への移動

## 3. 判定表
| 状態 | 判定 | 動作 |
| --- | --- | --- |
| ZIPだけ存在 | KEEP_ARCHIVE | ZIPを保持 |
| フォルダだけ存在 | KEEP_DIRECTORY | フォルダを保持 |
| ZIPとフォルダの全ファイルが一致 | DELETE_CANDIDATE | フォルダのみごみ箱へ移動する候補、ZIPは保持 |
| 差分がZIP側の補助ファイルのみ | DELETE_CANDIDATE_IGNORABLE | フォルダのみごみ箱へ移動する候補、差分を表示 |
| ZIPとフォルダに追加/不足/変更ファイルがある | MISMATCH | 両方保持、差分表示 |
| ZIPが壊れている、暗号化、読み取り不可、対応外 | UNVERIFIED | 両方保持、理由表示 |
| 対応候補が複数・曖昧 | AMBIGUOUS | 自動選択せず、両方保持 |

**HDDに同一データがあるかどうかは判定しない。** 同一階層のコピー時除外は既存の E/F/G コピーツール、階層をまたぐ重複整理は Krokiet 側の責務。

## 4. ZIPとフォルダの対応付け
1. ZIPと同じ親ディレクトリ内にある同名フォルダを第一候補とする（例: `photos.zip` ↔ `photos/`）。
2. ZIPの中に最上位ディレクトリが1つだけある場合は、そのディレクトリを剥がした構造とローカルフォルダを照合可能にする（例: ZIP内 `photos/a.jpg` ↔ `photos/a.jpg`）。
3. 単純な名前一致は**候補抽出のみ**であり、完全一致の根拠にしない。
4. 名前が異なる・複数の候補がある・対応が曖昧な場合は候補なしまたは AMBIGUOUS にして移動しない。名前の違いは §4.1 の接尾辞だけを候補抽出の対象にする。

### 4.1 名前が異なる組の候補抽出（実装済み）

`photos.zip` と `photos (1)/` のように、重複時に付く接尾辞だけが異なる組も候補にする。

- 完全一致するフォルダがある場合は必ずそちらを優先する。正規化名でのみ一致する場合は `nameVariant` として記録する。
- 対象の接尾辞は `\s*\(\d+\)$`、`\s*-\s*コピー(\s*\(\d+\))?$`、`\s*-\s*copy(\s*\(\d+\))?$`、`_\d+$`、`\s*のコピー(\s*\(\d+\))?$`。最大3回まで再帰的に取り除く。
- 名前の対応は候補抽出にのみ使い、削除候補の根拠にはしない。内容の完全一致確認は従来どおり必須。
- 正規化名で一致する候補が複数ある場合は `AMBIGUOUS` とし、自動選択しない。
- `nameVariant` は一覧・詳細・CSV / JSON に出力し、ユーザーが名前差を認識できるようにする。

### 4.2 補助ファイルのみの差分

OSやアーカイバが自動生成するファイルの有無だけが違う場合に `MISMATCH` とすると、実用上ほぼ全件が該当する。次の条件をすべて満たすときだけ `DELETE_CANDIDATE_IGNORABLE` とする。

- 差分が **ZIP側にのみ存在する** 補助ファイル／補助ディレクトリだけである
- 共通部分のパス集合が一致し、各ファイルのSHA-256も一致する
- フォルダ側にのみ存在するファイルが1つも無い

対象は `internal/verify/ignore.go` の許可リストに限定する（`__MACOSX/`、`.DS_Store`、`._*`、`Thumbs.db`、`desktop.ini`、`.Spotlight-V100`、`.Trashes`、`.fseventsd`、`.localized`、`.apdisk`、`ehthumbs.db`、`*.tmp`、`*.part`、`*.crdownload`）。

フォルダ側にしか無いファイルは対象外とする。ユーザーが意図して置いた可能性があり、削除すると情報が失われるため。`verifyContent` はフォルダ側に存在しないエントリを内容比較から除外し、共通部分だけをハッシュ比較する。

差分は判定理由と詳細に残し、移動確認ダイアログにも補助ファイルを含む旨を表示する。移動直前の再照合でも同じ判定を要求する。

## 5. 完全一致の定義と検証
- ZIP内の正規化された相対パス集合とフォルダ内の通常ファイル相対パス集合が一致すること
- 各対応ファイルの**展開後のバイト列**が一致すること（SHA-256等で双方をストリーミング比較）
- 空ディレクトリも保存対象として扱い、ディレクトリ構成の差異があれば自動移動不可
- ZIP内エントリの重複パス、絶対パス、`..`、Windowsで衝突するパス（大小文字の差、予約名、末尾の空白/ドット等）は UNVERIFIED
- ZIPエントリのCRCエラー、途中読み取りエラー、許容しない展開サイズ、暗号化などは UNVERIFIED
- ファイル属性/タイムスタンプは内容一致の必須条件にしない（ただし必要なら差分情報として表示）
- ファイルの同一性だけではなく、再解析時にファイルが差し替わっていないことを確認する。走査中に変化したものは UNVERIFIED
- ZIPに含まれないファイルがフォルダに1つでもあれば MISMATCH として自動移動不可
- ZIP内部に別名の外側トップディレクトリがあるケースや複数ルートのケースをテストする

### 4.3 アーカイブ形式の抽象化と 7z / RAR 対応（実装済み）

`.zip` / `.7z` / `.rar` を同じ判定経路で扱う。

- `internal/archive` が `Archive` インターフェース（`Variants` / `Open` / `StructureHash` など）を定義し、ZIP は標準ライブラリ、7z / RAR は 7-Zip CLI で実装する。判定は `internal/verify` が共通に行う。
- パスは ZIP と同じ `winpath.NormalizeArchiveEntry` で正規化する。絶対パス、`..`、予約名、末尾の空白/ドット、重複パス、ファイルとディレクトリの衝突は `ErrInvalid` として拒否し `UNVERIFIED` にする。
- `Encrypted = +` のエントリを含む書庫は `ErrEncrypted`。分割書庫・未対応圧縮方式は `ErrUnsupported`。どちらも `UNVERIFIED` として保持し、削除候補にしない。
- 7-Zip が見つからない場合は `ErrToolMissing`。理由を「7-Zip が必要」と明示して `UNVERIFIED` にする。ZIP の照合は 7-Zip なしでも動作する。
- 7-Zip の場所は設定ファイル `archiveTool` → PATH → 既定のインストール先の順で解決する。
- `strip-top` variant では表示パスを書き換えるため、元のアーカイブ内パスを `Entry.Original` に保持して読み出しに使う。これがないとトップ階層除去比較で内容を読めない。
- **7-Zip の `-so` は複数エントリを指定してもアーカイブ内の格納順で連結出力する**（指定順ではない）。そのためバッチ読み出しで高速化できず、1エントリ1プロセスになる。実測 約13ms/エントリ。速度はハッシュキャッシュで補う。
- 7-Zip は LGPL（`7z.dll` の一部に unRAR 制限）。本アプリは外部プロセスとして呼ぶだけで、バイナリを同梱・再配布しない。

### 5.1 一致判定アルゴリズム（現行実装・維持方針）

現在の `internal/engine/engine.go`、`internal/ziparchive/ziparchive.go`、`internal/verify/verify.go` の判定方式は基本方針として維持する。

1. **候補の抽出**: 原則として同一親ディレクトリの `photos.zip` と `photos/` のような同名の組を探す。名前の一致だけでは削除候補にしない。
2. **構造比較**: ZIP内部の相対パス（ZIP内の単一トップ階層を除いたパターンも考慮）と、解凍済みフォルダのファイル・ディレクトリ構成を比較する。余分なファイル、欠落、空ディレクトリの差があれば一致としない。
3. **容量の確認**: 対応するファイルの展開後サイズを比較し、相違があれば不一致とする。
4. **SHA-256の比較**: ZIP内の各ファイルをディスクに展開せずストリームで読み、展開後の内容のSHA-256を計算する。対応する解凍済みファイルもストリーミングでSHA-256を計算し、すべてのファイルでダイジェストが一致した場合だけ内容一致とみなす。ZIPの圧縮後バイト列同士は比較しない。
5. **検証中の変化・エラーを拒否**: 読み取り失敗、ZIPの不正、検証中のサイズ・更新日時変化などを検知した場合は一致確定しない。削除実行直前にも再検証する。

**設計判断:** SHA-256で全ファイル内容を検証する正確性を、ファイル名・サイズ・更新日時だけの高速判定より優先する。大容量データではI/Oと展開時間がかかるが、誤削除を避けるため、完全一致確認を省略する高速モードは削除判定に使用しない。

## 6. 安全性
- デフォルトでスキャン・プレビューのみ。ごみ箱への移動はGUI上で対象を選択して確認した場合のみ
- **MVPの「削除」はWindowsごみ箱への移動を指し、完全削除は行わない。** ごみ箱へ移動できない場合は完全削除へフォールバックせず中止し、理由を表示する
- 削除候補とその ZIP の組を一覧で表示し、移動対象のパスを明示する
- 操作前に対象とZIPを再検査し、変更があれば中止
- 移動対象は、内容一致を確認した組の「解凍済みフォルダのみ」「ZIPのみ」「ZIPとフォルダの両方」から明示選択する。ZIPとフォルダを自動でまとめて移動しない
- フォルダとZIPのごみ箱移動に先立ち、リンク/ジャンクション/リパースポイントの探索・辿り防止を保証する。安全を証明できない場合は拒否する
- ルート自身、ルート外、隠れた権限エラー等により完全検証できない対象を移動しない
- GUIでは複数候補の選択・一括確認による移動を許可するが、項目ごとに移動方法を選択し、確認画面に全対象件数・合計サイズ・対象パスを表示し、各対象を直前に再検証する。ZIPとフォルダの両方の移動は追加の警告と明示承認を必須とし、非対話的な無確認移動はMVP対象外
- 一方の移動だけ成功した場合は部分成功として残存状態を表示し、残った対象だけを再試行できる
- 移動履歴（日時、ZIP、移動対象、照合結果、成否）を保存し、エラーを握りつぶさない
- 大容量/ZIP bomb対策としてサイズ・件数などの上限を設定可能にする。上限超過は移動不可
- UNC/ネットワーク/光学ドライブなどごみ箱非対応の場所、容量不足、ロック中は移動せず理由を表示する

## 7. CLIインターフェース（補助・任意の設計案）
```powershell
archive-extract-cleaner scan "D:\Downloads" --recursive --format table
archive-extract-cleaner scan "D:\Downloads" --format json --output report.json
archive-extract-cleaner clean "D:\Downloads" --dry-run
archive-extract-cleaner clean "D:\Downloads" --interactive
```
- `scan`: 読み取り専用の照合結果を表示
- `clean --dry-run`: ごみ箱移動対象の予定を表示。移動しない
- `clean --interactive`: 各候補を再検証し、明示確認後のみWindowsごみ箱へ移動
- `--recursive`: 対象ルート以下を探索（初期値は再帰探索を想定）
- 終了コード: 0 正常、1 一部未検証・処理失敗、2 引数/設定エラー（最終定義は実装Issueで決定）
- 出力例: `KEEP_ARCHIVE`, `KEEP_DIRECTORY`, `DELETE_CANDIDATE`, `MISMATCH`, `AMBIGUOUS`, `UNVERIFIED`

## 7.1 GUI（主操作画面）
- Everythingのように**素早く一覧から探して選べる**WindowsデスクトップGUI。Everything自体との連携や全ドライブ常時索引は行わない
- 最初に対象フォルダを選ぶ。スキャンボタンと停止ボタンを設ける。再スキャン可能にする
- 結果は1行につき対応候補ペア（ZIP + 解凍済みフォルダ）または単独アイテム。列: 選択チェック、判定、名前、ZIP名、解凍済みフォルダ、親パス、対象サイズ、理由
- テキスト検索（名前・パス）、判定別フィルタ（全件/削除候補/不一致/未検証/保持）、列ソート、複数行選択を提供。削除候補のみ選択可能とする
- 列幅をドラッグで変更でき、ヘッダーと行を同期する。幅は再起動後も保存し、ハンドルのダブルクリックで自動調整する
- 行を選ぶとZIPとフォルダの対応・一致根拠・差異を詳細ペインに表示する。「解凍済みフォルダを開く」はフォルダ自体を開いて中身を表示し、「ZIPの場所を表示」は親フォルダでZIPを選択表示する
- 行を選ぶと詳細ペインに中身プレビューを表示する。ZIPは解凍せずセントラルディレクトリから、フォルダは読み取り専用で列挙する。両方存在する場合は「ZIP」「フォルダ」タブで切り替え、初期表示はZIPを優先する。名前・相対パス・種類・サイズ・更新日時を表示し、ディレクトリは展開/折りたたみ可能とする。名前・パス・拡張子で絞り込み、相対パスをコピーできる。ZIP内のパスを実ファイルのフルパスとして扱わない
- 一覧のファイル名・パスはテキスト選択でき、Ctrl+C、右クリックメニュー、詳細ペインのコピー操作で取得できる。空の項目はコピー操作を無効化する
- 上部または下部に総件数・削除候補件数・移動可能な推定容量・選択件数/容量を表示
- 選択した削除候補に対し「選択項目をごみ箱に移動」操作を提供。項目ごとに「解凍済みフォルダのみ」「ZIPのみ」「ZIPとフォルダの両方」を選択し、**移動前ダイアログ**で対象一覧/件数/容量を確認して最終承認させる。未検証・不一致は移動ボタン無効
- ごみ箱移動前に対象ごとに再照合し、変化した対象はスキップして理由を表示。ZIPもフォルダも明示選択時のみ移動する
- 大量の行は仮想スクロールで表示し、スキャン/照合はバックグラウンドで実行してUIを固めない。中断・エラー・進捗を画面表示する
- ごみ箱への移動後は該当行の状態と移動済み対象を更新し、結果を表示する。ZIPのみ移動した場合は残ったフォルダ、フォルダのみ移動した場合は残ったZIPを転送候補にする。両方移動した場合は転送候補から除外する
- GUI技術候補: Wails (Goバックエンド + WebViewフロントエンド)。実装前にWindows配布・起動速度・仮想リストを検証して最終決定する
- **MVPではZIPと解凍済みフォルダの明示的なごみ箱移動に限定**し、任意のファイル・フォルダの無条件削除や完全削除は提供しない


## 7.2 UX改善・削除の安全要件（2026-11-10 追加）
- **P0: Windowsでは、解凍済みフォルダおよびZIPの「削除」はWindowsのごみ箱への移動とする。** `os.RemoveAll` や完全削除APIによる通常UI操作は行わない。
- ごみ箱移動を実現できないドライブ・権限・環境では処理を中止し、理由を表示する。完全削除へフォールバックしない。
- ごみ箱から元の名前・元の場所に復元できることをWindows実機テストで保証する（ZIPファイル・フォルダ双方）。退避リネームにより復元名が変化しないようにする。
- ユーザー向けラベルは「ごみ箱に移動」。元の完全一致再検証と削除対象制約は維持する。
- **P1: 一覧グリッドの列幅はヘッダー境界ドラッグで変更可能**とし、ヘッダーと行の幅が一致すること。変更幅を再起動後も保持する。
- **P1: ファイル名・パス・判定理由の文字列を選択してコピー可能**とする。右クリックまたは詳細ペインからファイル名・ZIPパス・フォルダパスをコピーする操作も提供する。
- コピー、リサイズ、ソート、行選択、仮想スクロールが競合しないことを受け入れ条件とする。
- **2026-11-11追加（#28）:** 選択列のチェックボックス上でマウス／ペンを押したまま上下にドラッグすると、開始時のチェック状態（未選択なら選択、選択済みなら解除）を通過した選択可能行へ統一適用する。往復してもトグルしない。選択不能行は変更しない。Pointer Eventsで開始・通過・終了を管理し、選択件数・容量はドラッグ中に更新する。上下端付近では自動スクロールし、仮想スクロールの行DOM再利用時も行IDとインデックスで対象を判定する。行読み込み待ち・ページ切替・ウィンドウ外のpointerup/cancel・blur・再描画でドラッグ状態を残さない。タッチは通常スクロールを優先し、既存のShift+クリック範囲選択・列幅変更・文字選択・プレビュー・ダブルクリック・右クリックを壊さない。
- 対応Issue: #13（ごみ箱/P0）、#14（列幅/P1）、#15（コピー/P1）、#28（ドラッグ選択/P2）。
- **2026-11-11追加（#23）:** 内容一致を確認した組について「解凍済みフォルダのみ」「ZIPのみ」「ZIPとフォルダの両方」を項目ごとに選択できる。両方移動は最後のローカルコピーを失う可能性を警告し、追加承認を必須とし、既定選択にしない。部分失敗は残存状態を表示して残った対象のみ再試行できる。ZIP・フォルダ双方のごみ箱復元を実機確認する。
- **2026-11-11追加（#22）:** 解凍済みフォルダを開く操作はフォルダ自体を開いて中身を表示し、ZIPは親フォルダを開いて対象を選択表示する。ZIPとフォルダが両方ある場合は詳細画面で操作を分ける。移動済み・消失・アクセス不可の場合は誤った場所を開かず理由を表示する。

- **2026-11-11追加（#26）:** 詳細ペインのプレビューは行切替時に読み込み状態・キャンセル・結果適用先を管理し、前の行の内容を一瞬表示しない。ZIP Slip相当の不正パス、壊れたZIP、リンク/ジャンクション、読み取りエラーを安全に処理する。最大2万エントリまで表示し、仮想スクロールでUIを固めない。プレビュー表示は一致判定・検証結果を変更しない。

## 7.3 multi-drive-copyとの連携（実装済み）
- GUIに「残ったデータをE/F/Gへコピー」を追加し、整理後のZIP/フォルダをレビューして既存 `tonbiattack/multi-drive-copy` へ引き渡す。
- ZIPと解凍済みフォルダが完全一致する組はZIPだけを推奨し、フォルダしかない場合はフォルダを推奨する。
- 不一致・未検証・曖昧な組はZIPとフォルダを要確認として表示し、既定では選択しない。ユーザーが明示選択したものだけを転送対象にする。
- 転送前にパスの存在を再確認し、スキャン結果にないパス・消失したパスは起動しない。スキャン中・ごみ箱移動中も起動しない。
- 設定ファイルの `multiDriveCopy.scriptPath` でスクリプト位置を指定する。空欄時は `%LocalAppData%\Programs\MultiDriveCopy\MultiDriveCopy.ps1` を使う。
- `multiDriveCopy.preset` が空ならmulti-drive-copyの設定画面を開き、指定時は保存済みプリセットの直接実行モードを使う。
- 転送処理そのものはmulti-drive-copyが担当する。本アプリはコピー成功を推測せず、元データを自動削除しない。
- 引数渡しは `exec` により引用符・空白・日本語を安全に扱う。既存の小規模な引数連携は後方互換とする。
- Windowsのコマンドライン長制限を超える場合は、`{"sources":[...]}` 形式のUTF-8 JSONマニフェストを書き、正式インターフェース `MultiDriveCopy.ps1 -SourceListFile <manifest>` で引き渡す。
- マニフェスト起動前に受信側の `Read-SourceListFile` で読込検証し、失敗時はコピーを起動しない。古い受信側で未対応の場合は更新を促す。
- `-Preset` と `-SourceListFile` は受信側で併用禁止のため、大量パスでプリセット指定がある場合はプリセットを暗黙適用せずレビュー画面を開き、警告を表示する。
- 一時マニフェストは24時間より古いものを次回起動時に削除する。子プロセスが読み込む前には削除しない。
- 対応Issue: #16, #18。

### 7.3.1 整理と転送の独立性（ユーザー操作仕様）
- **スキャン・照合・重複した解凍済みフォルダのごみ箱移動は、転送と独立した操作**。整理を実行しただけではmulti-drive-copyを起動せず、E/F/Gへのコピーは始まらない。
- ユーザーは「整理だけ行って終了する」か、「整理後に『残ったデータをE/F/Gへコピー』を明示的に押して転送する」かを選べる。整理の完了後に転送しなくても正常な利用方法とする。
- 転送ボタンを押した場合でも、転送候補のレビュー・選択を経てmulti-drive-copyに渡す。転送先やコピー後の元データのごみ箱移動はmulti-drive-copy側で操作する。
- **重複解凍フォルダの整理**と**転送後に検証済みのコピー元をごみ箱へ移動すること**は別工程。後者は受信側でデフォルトOFFの明示的なオプションと最終確認を必要とする。
- 画面上部のワークフロー表示は処理の案内であり、整理→転送→元データ整理の全ステップの実行を強制しない。転送しない選択で自動起動・自動削除しない。

## 7.4 整理→転送ワークフロー（実装済み）
- 画面上部に「整理（本アプリ） → 転送・検証（multi-drive-copy） → 元データ整理（multi-drive-copy）」の段階表示を設ける。
- スキャン完了・転送起動などの状態に応じて現在段階を更新する。アプリ再起動時は初期段階に戻る。
- コピー・全転送先検証・元データのごみ箱移動の結果は、受信側の明示的な結果プロトコルが実装されるまで本アプリへ反映しない。子プロセス起動成功をコピー完了とみなさない。
- エラー・中止時は転送ボタンから再試行できる。元データの完全削除は行わない。
- 対応Issue: #19。

## 8. 構造と性能
- ZIPをディスクに丸ごと解凍しない。各エントリをストリーミング展開・ハッシュ計算
- CPU/ディスク負荷制御のため並列度を設定可能にする
- 処理中の進捗、キャンセル（Ctrl+C）、検査済み件数、比較バイト数を表示する
- Windowsのパス長、日本語ファイル名、複数階層、大容量ファイルを考慮

### 7.5 スキャン結果の書き出し（実装済み）
- ツールバーから CSV / JSON を選び、保存ダイアログで出力先を指定する。形式が空なら CSV。
- 出力対象はスキャン結果のスナップショット。画面の検索・フィルタ・ソート状態には依存せず、判定順・親パス・名前の順で安定させる。
- CSV の列は固定（`internal/report/report.go` の `CSVHeader`）。`details` は ` | ` で連結する。
- JSON は `generatedAt` / `summary` / `roots` / `items` を持つ。`details` が空なら省略し、`roots` は `null` ではなく空配列にする。
- 一時ファイルへ書いてから置き換える。書き出し失敗時に壊れたファイルや一時ファイルを残さない。
- 書き出しは読み取り専用で、削除の可否判定や移動処理に影響しない。書き出したファイルを編集してもアプリ側の判定は変わらない。
- 拡張子が無い場合は形式に合わせて付与する。別の拡張子が付いている場合は付け替える（上書き確認はダイアログ側に任せる）。

### 8.1 照合の並列実行（実装済み）
- ZIP/フォルダの組（およびフォルダ単独項目）を単位として、照合フェーズのみワーカー並列で実行する。
- 並列度は設定ファイルの `workers`。`0` または未指定は自動（CPU数、上限8）、`1` は従来どおり逐次、上限は16。
- 候補フォルダの対応付けは並列化前に逐次で確定させ、走査キャッシュの書き換えをワーカーへ持ち込まない。
- 結果はタスク順に固定して `items` へ書き込み、最後に従来と同じ `SortItems` を適用する。**判定・理由・件数・比較バイト数は並列度に依存しない。**
- 進捗通知は共有カウンタから100ms間隔で間引き、`completed`・`bytes` を単調増加で報告する。`etaMs` は照合開始からの経過と完了件数から算出し、算出不能時は `-1`。
- 中断（`context` キャンセル）時は未着手タスクを投入せず、実行中タスクの完了を待って `context.Canceled` を返す。途中結果は破棄する。
- 安全性に関わる検証（SHA-256比較、検証前後の再走査、ZIPのサイズ・更新日時確認）はワーカー内でも逐次実装と同一の処理を行う。

### 8.2 差分スキャンとハッシュキャッシュ（実装済み）
- 2種類のキャッシュを持つ。`archives.json` は ZIP エントリの展開後SHA-256、`scan.json` は前回の項目判定とフォルダ指紋を保持する。
- 保存はどちらも一時ファイル＋`os.Rename` の原子的書き込み。中断時に壊れたファイルを残さない。
- `SchemaVersion` を上げると古いキャッシュは破棄される。破損・欠損・スキーマ不一致は「キャッシュなし」として扱い、完全スキャンへ戻る。スキャンを止めない。

**再利用の条件**（すべて一致した場合だけ）:

1. 前回の項目が `Cacheable`（`StatusReady` かつ未移動かつ `UNVERIFIED` でない）
2. 項目IDが同じ（ZIPとフォルダの対応付けが変わっていない）
3. ZIPのパス・サイズ・更新時刻が一致
4. ZIPの**構造指紋**が一致。指紋はセントラルディレクトリの `Name`・`Method`・`CRC32`・`CompressedSize64`・`UncompressedSize64` をソートしてSHA-256化したもの。圧縮データは読まない
5. フォルダの指紋が一致。指紋はファイル（小文字相対パス・サイズ・更新時刻）とディレクトリの一覧をソートしてSHA-256化したもの

3と4を分ける理由は、サイズと更新時刻だけでは同一性を保証できないため。**同サイズ・同更新時刻で中身だけ差し替えたZIP**は3を通るが4で落ちる。

- ZIPエントリのハッシュは構造指紋をキーに保存し、取得時はエントリごとに `CRC32` とサイズも突き合わせる。1つでも合わなければキャッシュ全体を捨てて再計算する。
- 内容比較が最後まで完了したときだけハッシュを保存する。途中で失敗した ZIP を「検証済み」として残さない。

**削除安全性との関係（不変条件）**

- 差分スキャンの結果は「表示と並び順の高速化」にだけ寄与する。削除の可否は `Verdict` で決まり、`Verdict` は再利用時も前回の値と同一。
- ごみ箱移動直前の `verify.Verify` には `Hashes` を渡さない。スキャン結果がキャッシュ由来でも、移動時の根拠は必ず実体の再計算にする（`moves.go`）。
- したがって「キャッシュがあるから誤削除される」経路は存在しない。キャッシュが壊れていても最悪で再検証が増えるだけ。

**操作**

- 通常の「スキャン」は差分スキャン。`App.Rescan` / 「完全再スキャン」は `Full: true` でキャッシュを無視する。
- `App.ClearCache` / 設定ダイアログの「キャッシュを破棄」で両方のキャッシュを削除する。
- 差分スキャンは対象ルートが1つのときに有効。複数ルートでは完全スキャンと同じ経路を通る。
- キャッシュの上限は ZIP 指紋20000件・ルート8件。超過時は最終参照が古いものから削除する。

### 8.3 容量ダッシュボード（実装済み）
- 一覧上部にスキャン全体の容量内訳を表示する。`internal/dashboard` が集計し、`RowPage.Dashboard` で返す。
- 分類は「回収見込み」「ZIPを保持」「フォルダを保持」「削減対象外」「ごみ箱へ移動した容量」。
- **回収見込みは `DELETE_CANDIDATE` と `DELETE_CANDIDATE_IGNORABLE` のみ**。`MISMATCH` / `AMBIGUOUS` / `UNVERIFIED` は「削減対象外」に分離し、回収見込みへ加算しない。
- 代表サイズは判定ごとに決める。`KEEP_ARCHIVE` はZIPサイズ、削除候補はフォルダサイズ、それ以外はフォルダサイズを優先する。
- 移動済み（`StatusDeleted`）は判定内訳とは別に `Recycled` として数え、内訳の合計に含めない（移動後は判定が `KEEP_*` に変わるため二重計上を避ける）。
- 移動集計は `Succeeded` / `Partial` / `Failed` / `Skipped` を件数とサイズで持つ。`MovedBytes` は**実際にごみ箱へ移せた容量**で、要求容量とは別に積む。複数回の移動は累積する。
- 表示はスキャン全体の値とし、一覧の検索・フィルタ状態に依存しない。絞り込み中は `Filtered` と `FilteredCount` を併記して区別する。
- **ごみ箱へ移した容量はディスクの空き容量増加と同義ではない。** ごみ箱を空にするまで物理領域は残るため、その旨を常時表示する。
- 集計は表示専用で、削除の可否判定や移動処理に影響しない。


## 9. テスト・受け入れ条件
- ZIPのみ、フォルダのみ、完全一致、不一致（追加/欠落/内容変更）、破損ZIP、暗号化ZIP、空フォルダ
- ZIP内のトップディレクトリあり/なし、パス衝突、Zip Slip、ジャンクション、シンボリックリンク
- 同じサイズ・異なる内容、実行中のファイル変更、アクセス拒否
- **ドライランで一切移動されない**
- **内容不一致・判定不能の対象は自動移動されない**
- **ZIP自体は自動削除・自動移動されない**
- ごみ箱移動が行われる場合は直前の再照合と明示確認を必須とする
- **ごみ箱移動に失敗した場合も完全削除されない**
- NTFSローカルドライブで対象がWindowsごみ箱に現れ、元のパスへ復元できる（ZIPファイル・フォルダ双方）
- ZIPのみ／フォルダのみ／両方の移動方法を項目ごとに選択でき、存在しない対象の方法は無効になる
- 両方移動は追加警告と明示チェックなしに実行されない
- 一方が失敗した部分成功で残存状態が正しく表示され、残った対象だけを再試行できる
- ZIPのみ移動後は残ったフォルダ、フォルダのみ移動後は残ったZIPが転送候補になる
- フォルダのExplorer表示は中身を開き、ZIPは親フォルダで選択表示する。移動済み・消失時は理由を表示する
- Explorer表示は空白・日本語・`&`・`#`・括弧・アポストロフィ・長いパスで対象を正しく選択する
- ZIPのみ保持の行で「エクスプローラーで表示」・ダブルクリック・「ZIPの場所を表示」が対象ZIPを選択する
- 行選択時にZIPのみ／フォルダのみ／両方のプレビューを表示でき、両方はタブで切り替えられる
- プレビューの検索・階層展開・相対パスコピーが動作し、大量エントリでもUIが固まらない
- 不正ZIP・消失パス・リンク・特殊文字・日本語ファイル名を安全に表示し、行切替時に前の一覧が残らない
- チェックボックスの上下ドラッグで開始状態に統一して複数行を選択・解除でき、往復でトグルしない
- ドラッグ中に選択件数・容量が更新され、上下端で自動スクロールし、選択不能行を含まない
- ドラッグ後も通常行クリック・Shift+クリック・列幅変更・文字選択・プレビュー・ダブルクリックが動作する
- multi-drive-copy 連携でZIP優先の推奨と要確認項目が分離され、要確認を暗黙に転送しない
- 日本語・空白・特殊文字・大量パスを `sources` マニフェスト経由でも欠落なく引き渡せる
- `-Preset` と `-SourceListFile` の併用禁止時も、起動失敗や無確認コピーにならず警告される
- ワークフロー表示がスキャン・転送起動・再起動で矛盾しない
- 照合の並列度を変えても判定・理由・件数・比較バイト数が一致する（`workers=1` と `workers=8` を比較）
- 並列照合の進捗で `completed` が `total` を超えず、完了時に一致する
- 補助ファイルのみの差分は `DELETE_CANDIDATE_IGNORABLE` になり、共通内容が違えば `MISMATCH` になる
- フォルダ側にしか無い補助ファイルでは削除候補にしない
- AI推薦があっても `Item.Deletable()` と移動可否は変わらない
- `UNVERIFIED` と既存の削除候補はAIへ送らない
- 名前差のある組を候補にできるが、内容が不一致なら削除候補にならない
- 名前差の組が複数あるときは `AMBIGUOUS` になり、自動選択されない
- CSV / JSON の書き出しで、カンマ・引用符・日本語・改行を含むパスが壊れない
- CSV / JSON の書き出し失敗時に一時ファイルが残らない
- 差分スキャンと完全再スキャンで判定・件数・削除可否が一致する
- フォルダの内容変更・ファイル追加・空ディレクトリ追加・リネームを差分スキャンが検出する
- 同サイズ・同更新時刻でZIPの中身だけ差し替えた場合に再利用しない
- キャッシュが壊れている・無い・スキーマが古い場合に完全スキャンへ戻る
- キャッシュがあっても、スキャン後にフォルダを変更した場合は移動直前の再照合でスキップされる
- `UNVERIFIED` と移動途中の項目はキャッシュに保存されない
- 回収見込みに `MISMATCH` / `AMBIGUOUS` / `UNVERIFIED` を含めない
- 一覧を絞り込んでもダッシュボードはスキャン全体の値を示し、絞り込み中であることが分かる
- 移動後に回収見込みが減り、移動した容量が実績として増える（混同しない）
- 部分成功時は、実際に移せた容量だけを「移動した容量」に加算する
- 7z / RAR で一致・不一致・破損・暗号化・パス不正を正しく判定する
- 7-Zip 未インストール時に 7z / RAR を `UNVERIFIED` にし、削除候補にしない
- 未対応形式（`.tar` など）を走査対象にも削除候補にもしない
- 7z でもスキャン後の変更が移動直前の再照合で検出される

### 10.1 AI推薦レイヤー（実装済み・削除権限なし）

AIを削除判断に使う場合の設計境界を定める。

- **AIは推薦のみ**。削除可否を決めるのは `verify` の完全一致判定（`DELETE_CANDIDATE` / `DELETE_CANDIDATE_IGNORABLE`）だけとする。AIの出力で `Item.Deletable()` を真にしない。
- 対象は `MISMATCH` / `AMBIGUOUS` のみ。`UNVERIFIED` は内容を確認できないためAIにも送らない。
- 送信するのは `advisor.Evidence` に集約した証拠（件数・比率・代表例・兄弟名）だけ。ファイル内容とフルパス一覧は送らない。
- ファイル名等は指示ではなくデータとして扱う。プロンプト内で `<evidence>` タグに隔離し、応答はJSONスキーマで検証し、未知の `decision` や範囲外の `confidence` は拒否する。
- 既定は無効。`ai.enabled` が false の間はネットワークへアクセスしない。APIキーは環境変数から読み、設定ファイルへ書かない。
- `http://` の接続先は `ai.allowInsecure` を明示した場合のみ許可する。
- 推薦は操作ログへ `ai_suggestion` として、モデル名・判断・信頼度・証拠ハッシュとともに記録する。
- 証拠は `advisor.EvidenceHash` でハッシュ化し、同一証拠の再問い合わせ抑制と監査に使う。
