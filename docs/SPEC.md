# 仕様書 — archive-extract-cleaner

## 1. 背景と目的
ダウンロードした ZIP と解凍済みフォルダがローカルに混在している。HDDへ移す前に、ZIPが残っているならZIPを優先し、内容が同一の解凍済みフォルダを整理したい。一方、ZIPが無くフォルダだけならフォルダを保持してコピー対象にしたい。

本ツールの責務は **ローカルの「圧縮ファイル vs 解凍済みフォルダ」の照合と安全な削除候補抽出** のみ。HDD転送・HDD上の重複判定・別階層の一般的な重複検出を行わない。

## 2. 対象と非対象
- 初期OS: Windows 11。実装言語: Go。**GUI中心**で操作（CLIは補助・任意）
- MVP対応アーカイブ: .zip（ZIP64、UTF-8/CP437等のファイル名に留意。解釈不能は要確認）
- 非対象（初期）: .7z/.rar、暗号化 ZIP の中身判定、HDDとの比較、汎用重複ファイル検索、同期・コピー
- 入力: 指定した1つ以上のローカルルート。再帰的に走査
- 出力: GUI一覧表示、必要に応じたJSONレポート、明示した場合のみ安全な削除処理

## 3. 判定表
| 状態 | 判定 | 動作 |
| --- | --- | --- |
| ZIPだけ存在 | KEEP_ARCHIVE | ZIPを保持 |
| フォルダだけ存在 | KEEP_DIRECTORY | フォルダを保持 |
| ZIPとフォルダの全ファイルが一致 | DELETE_CANDIDATE | フォルダのみ削除候補、ZIPは保持 |
| ZIPとフォルダに追加/不足/変更ファイルがある | MISMATCH | 両方保持、差分表示 |
| ZIPが壊れている、暗号化、読み取り不可、対応外 | UNVERIFIED | 両方保持、理由表示 |
| 対応候補が複数・曖昧 | AMBIGUOUS | 自動選択せず、両方保持 |

**HDDに同一データがあるかどうかは判定しない。** 同一階層のコピー時除外は既存の E/F/G コピーツール、階層をまたぐ重複整理は Krokiet 側の責務。

## 4. ZIPとフォルダの対応付け
1. ZIPと同じ親ディレクトリ内にある同名フォルダを第一候補とする（例: `photos.zip` ↔ `photos/`）。
2. ZIPの中に最上位ディレクトリが1つだけある場合は、そのディレクトリを剥がした構造とローカルフォルダを照合可能にする（例: ZIP内 `photos/a.jpg` ↔ `photos/a.jpg`）。
3. 単純な名前一致は**候補抽出のみ**であり、完全一致の根拠にしない。
4. 名前が異なる・複数の候補がある・対応が曖昧な場合は候補なしまたは AMBIGUOUS にして削除しない。将来的に明示マッピングを検討する。

## 5. 完全一致の定義と検証
- ZIP内の正規化された相対パス集合とフォルダ内の通常ファイル相対パス集合が一致すること
- 各対応ファイルの**展開後のバイト列**が一致すること（SHA-256等で双方をストリーミング比較）
- 空ディレクトリも保存対象として扱い、ディレクトリ構成の差異があれば自動削除不可
- ZIP内エントリの重複パス、絶対パス、`..`、Windowsで衝突するパス（大小文字の差、予約名、末尾の空白/ドット等）は UNVERIFIED
- ZIPエントリのCRCエラー、途中読み取りエラー、許容しない展開サイズ、暗号化などは UNVERIFIED
- ファイル属性/タイムスタンプは内容一致の必須条件にしない（ただし必要なら差分情報として表示）
- ファイルの同一性だけではなく、再解析時にファイルが差し替わっていないことを確認する。走査中に変化したものは UNVERIFIED
- ZIPに含まれないファイルがフォルダに1つでもあれば MISMATCH として自動削除不可
- ZIP内部に別名の外側トップディレクトリがあるケースや複数ルートのケースをテストする

### 5.1 一致判定アルゴリズム（現行実装・維持方針）

現在の `internal/engine/engine.go`、`internal/ziparchive/ziparchive.go`、`internal/verify/verify.go` の判定方式は基本方針として維持する。

1. **候補の抽出**: 原則として同一親ディレクトリの `photos.zip` と `photos/` のような同名の組を探す。名前の一致だけでは削除候補にしない。
2. **構造比較**: ZIP内部の相対パス（ZIP内の単一トップ階層を除いたパターンも考慮）と、解凍済みフォルダのファイル・ディレクトリ構成を比較する。余分なファイル、欠落、空ディレクトリの差があれば一致としない。
3. **容量の確認**: 対応するファイルの展開後サイズを比較し、相違があれば不一致とする。
4. **SHA-256の比較**: ZIP内の各ファイルをディスクに展開せずストリームで読み、展開後の内容のSHA-256を計算する。対応する解凍済みファイルもストリーミングでSHA-256を計算し、すべてのファイルでダイジェストが一致した場合だけ内容一致とみなす。ZIPの圧縮後バイト列同士は比較しない。
5. **検証中の変化・エラーを拒否**: 読み取り失敗、ZIPの不正、検証中のサイズ・更新日時変化などを検知した場合は一致確定しない。削除実行直前にも再検証する。

**設計判断:** SHA-256で全ファイル内容を検証する正確性を、ファイル名・サイズ・更新日時だけの高速判定より優先する。大容量データではI/Oと展開時間がかかるが、誤削除を避けるため、完全一致確認を省略する高速モードは削除判定に使用しない。

## 6. 安全性
- デフォルトでスキャン・プレビューのみ。実削除はGUI上で対象を選択して確認した場合のみ
- 削除候補とその ZIP の組を一覧で表示し、削除対象のパスを明示する
- 操作前に対象とZIPを再検査し、変更があれば中止
- 削除対象は解凍済みフォルダのみ。アーカイブは自動削除しない
- フォルダ丸ごとの再帰削除に先立ち、リンク/ジャンクション/リパースポイントの探索・辿り防止を保証する。安全を証明できない場合は拒否する
- ルート自身、ルート外、隠れた権限エラー等により完全検証できないフォルダを削除しない
- GUIでは複数候補の選択・一括確認による削除を許可するが、確認画面に全対象件数・合計サイズ・対象パスを表示し、各対象を直前に再検証する。非対話的な無確認削除はMVP対象外
- 削除履歴（日時、ZIP、削除対象、照合結果、成否）を保存し、エラーを握りつぶさない
- 大容量/ZIP bomb対策としてサイズ・件数などの上限を設定可能にする。上限超過は削除不可

## 7. CLIインターフェース（補助・任意の設計案）
```powershell
archive-extract-cleaner scan "D:\Downloads" --recursive --format table
archive-extract-cleaner scan "D:\Downloads" --format json --output report.json
archive-extract-cleaner clean "D:\Downloads" --dry-run
archive-extract-cleaner clean "D:\Downloads" --interactive
```
- `scan`: 読み取り専用の照合結果を表示
- `clean --dry-run`: 削除対象の予定を表示。削除しない
- `clean --interactive`: 各候補を再検証し、明示確認後のみ削除
- `--recursive`: 対象ルート以下を探索（初期値は再帰探索を想定）
- 終了コード: 0 正常、1 一部未検証・処理失敗、2 引数/設定エラー（最終定義は実装Issueで決定）
- 出力例: `KEEP_ARCHIVE`, `KEEP_DIRECTORY`, `DELETE_CANDIDATE`, `MISMATCH`, `AMBIGUOUS`, `UNVERIFIED`

## 7.1 GUI（主操作画面）
- Everythingのように**素早く一覧から探して選べる**WindowsデスクトップGUI。Everything自体との連携や全ドライブ常時索引は行わない
- 最初に対象フォルダを選ぶ。スキャンボタンと停止ボタンを設ける。再スキャン可能にする
- 結果は1行につき対応候補ペア（ZIP + 解凍済みフォルダ）または単独アイテム。列: 選択チェック、判定、ZIP名、解凍済みフォルダ、親パス、対象サイズ、理由
- テキスト検索（名前・パス）、判定別フィルタ（全件/削除候補/不一致/未検証/保持）、列ソート、複数行選択を提供。削除候補のみ選択可能とする
- 行を選ぶとZIPとフォルダの対応・一致根拠・差異を詳細ペインに表示。エクスプローラーで場所を開ける
- 上部または下部に総件数・削除候補件数・削除可能な推定容量・選択件数/容量を表示
- 選択した削除候補に対し「選択項目を削除」操作を提供。**削除前ダイアログ**で対象一覧/件数/容量を確認して最終承認させる。未検証・不一致は削除ボタン無効
- 実削除前に対象ごとに再照合し、変化した対象はスキップして理由を表示。ZIPは削除対象外
- 大量の行は仮想スクロールで表示し、スキャン/照合はバックグラウンドで実行してUIを固めない。中断・エラー・進捗を画面表示する
- ごみ箱への移動後は該当行の状態を更新し、結果を表示する。選択状態の保持/解除ルールを定義して誤操作を防ぐ
- GUI技術候補: Wails (Goバックエンド + WebViewフロントエンド)。実装前にWindows配布・起動速度・仮想リストを検証して最終決定する
- **MVPでは解凍済みフォルダの削除に限定**し、アーカイブ本体の削除や任意のフォルダ削除は提供しない


## 7.2 UX改善・削除の安全要件（2026-11-10 追加）
- **P0: Windowsでは、解凍済みフォルダの「削除」は原則としてWindowsのごみ箱への移動とする。** `os.RemoveAll` による完全削除は通常のUI操作から実行してはならない。
- ごみ箱移動を実現できないドライブ・権限・環境では処理を中止し、理由を表示する。完全削除へフォールバックしない。
- ごみ箱から元の名前・元の場所に復元できることをWindows実機テストで保証する。退避リネームにより復元名が変化しないようにする。
- ユーザー向けラベルは「ごみ箱に移動」。元の完全一致再検証と削除対象制約は維持する。
- **P1: 一覧グリッドの列幅はヘッダー境界ドラッグで変更可能**とし、ヘッダーと行の幅が一致すること。変更幅を再起動後も保持する。
- **P1: ファイル名・パス・判定理由の文字列を選択してコピー可能**とする。右クリックまたは詳細ペインからファイル名・ZIPパス・フォルダパスをコピーする操作も提供する。
- コピー、リサイズ、ソート、行選択、仮想スクロールが競合しないことを受け入れ条件とする。
- 対応Issue: #13（ごみ箱/P0）、#14（列幅/P1）、#15（コピー/P1）。

## 7.3 multi-drive-copyとの連携（実装予定）
- 整理後のデータを既存 `tonbiattack/multi-drive-copy` へ引き渡すため、GUIに「残ったデータをE/F/Gへコピー」を追加する。
- ZIPと解凍済みフォルダが完全一致する組はZIPを優先し、フォルダしかなければフォルダを対象にする。
- 不一致・未検証・曖昧な組については暗黙にデータを除外しない。ユーザーが転送対象を明示選択するレビュー画面を設ける。
- 転送前に対象パスの存在とスキャン結果の鮮度を確認し、対象件数・パス一覧を表示する。
- 転送処理そのものはmulti-drive-copyが担当する。コピー元を削除するかどうかもmulti-drive-copy側で管理し、連携元から自動削除しない。
- 現行multi-drive-copyは引数でパスを受け取る。大量パスはWindowsコマンドライン長制限があるため、JSONのコピー元一覧ファイルを使う受け渡し方式を推奨する。
- 対応Issue: #16。受け取り側の変更は `multi-drive-copy` #7 を参照。

## 8. 構造と性能
- ZIPをディスクに丸ごと解凍しない。各エントリをストリーミング展開・ハッシュ計算
- CPU/ディスク負荷制御のため並列度を設定可能にする（MVPは逐次でも可）
- 処理中の進捗、キャンセル（Ctrl+C）、検査済み件数、比較バイト数を表示する
- Windowsのパス長、日本語ファイル名、複数階層、大容量ファイルを考慮

## 9. テスト・受け入れ条件
- ZIPのみ、フォルダのみ、完全一致、不一致（追加/欠落/内容変更）、破損ZIP、暗号化ZIP、空フォルダ
- ZIP内のトップディレクトリあり/なし、パス衝突、Zip Slip、ジャンクション、シンボリックリンク
- 同じサイズ・異なる内容、実行中のファイル変更、アクセス拒否
- **ドライランで一切削除されない**
- **内容不一致・判定不能の対象は自動削除されない**
- **ZIP自体は自動削除されない**
- 実削除が行われる場合は直前の再照合と明示確認を必須とする

## 10. 将来拡張候補（MVP外）
7z/RAR、異なる名前のフォルダの候補発見、差分の詳細表示、HTMLレポート、複数ルートを跨ぐ候補マッチング。
